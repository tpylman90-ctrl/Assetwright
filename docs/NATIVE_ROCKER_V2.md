# Native rocker channel — V2 development (research only)

The first three native operations and the accepted measured inverse v1 checkpoint remain frozen. The original blindfamily benchmark was inspected, so it is no longer pristine. The v1 measured-geometry workflow is now manual reproduction only, to prevent an accidental new release from exposed holdout data.

## Real fourth operation

- recess_lower_rocker deforms **the existing connected hull loft** at the lower sidewall, with angular and longitudinal smoothstep windows and extra axial stations. Its strength is continuous in [0,1].
- The Android default still uses zero strength. No new loose body overlays, downloaded geometry, or foreign model inference are introduced.
- applyExpandedProgram is a distinct four-operation bounded V2 executor: sculpt_cockpit_shoulder, recess_lower_rocker, recess_rear_socket, loft_rear_nacelle. The V1 applyProgram and constructionOrder have not changed.
- No trained V2 text selector or learned planner is asserted. The command sequence is hand-reviewed engineering scaffolding for a future learner.

## Development proof

NativeRockerV2Test exports two original development vehicle configurations, each with baseline, three channel strengths (.25, .50, .90) and a composed four-operation output (.725 each), for ten original Kotlin-generated GLBs and SHA-256 provenance files.

The independent audit_native_rocker_v2.py must verify the corresponding lower-hull GLB stations actually move monotonically (at least 0.012 m between levels, >0.075 m cumulative), a real single closed hull with no invalid or nonmanifold edges, a stable number of mesh parts, original topology gain, the 12K-triangle development cap, and preservation of the channel in the four-step GLB. Negative tests reject duplicates, unknown commands, NaN/overrange strengths, wrong order, and incompatible engine counts.

The native-rocker-v2 GitHub Actions workflow uploads original GLBs and measurements for human visual review **without promoting the research to Android or a new model release**. No false claim of Class-A surface continuity, Boolean openings, fully welded engine transitions, or production appearance is made.

## Visual review additions

The V2 research workflow also renders 60 lightweight CPU diagnostic PNGs from the original source-hashed GLBs: two development families, baseline/strong channel/composed variants, five camera views (front/side/top/rear/front-three-quarter), and clay/wire modes. These files are generated by a rendering-only Python tool, not a geometry teacher or external mesh generator. The preview manifest hashes every PNG against its original GLB source; the independent topology and shape audit still gates the result first. Human inspection is required before any fidelity or production claim.

## Preventing repeated legacy holdout evaluation

The original native-operator student and strength-calibration GitHub Actions workflows are now manual-reproduction-only, just like the original three-operation measured inverse workflow. Their past holdout templates have been inspected and cannot be used as fresh blind promotion evidence. One legacy student workflow was automatically rerun by the initial V2 bridge edit before this safeguard; that run is only a historical reproduction, not independent V2 evidence, and no student weights from it are installed in Android. New student checkpoint promotion requires new independent partitions and explicit non-regression gates.

## November 3 visual feedback — first V2 presentation rejected

The first screenshots of the V2 rocker experiments exposed an important false-positive risk: although the source-hashed closed hull responded mathematically, the side elevations looked almost identical, the body was still a thin slab, and the 16-segment cockpit and hull were visibly faceted. The first V2 structural pass is preserved in git, but it is **not visually accepted** as a modeling-quality milestone.

The next research-only correction increases hull angular sampling in the two development fixtures to 32 segments; creates a wider recessed side-channel with subtle upper/lower lips in the SAME continuous hull; and raises the lower-hull central profile by up to 0.11 m at full strength. The independent GLB audit now requires the *side elevation's actual underside vertices* to move monotonically (>0.075 m cumulative), in addition to the previously enforced channel half-span condition (tightened to >0.15 m). This rejects an operation that only moves hidden X coordinates while looking unchanged from the side.

The diagnostic renderer also uses a fitted camera and directional shading to expose, not hide, shape weaknesses. These are reuses of inspected **development** families; results are never represented as unseen generalization. The V1 model/checkpoints and production Android presets remain untouched. Even if the new checks pass, human visual approval remains mandatory.
