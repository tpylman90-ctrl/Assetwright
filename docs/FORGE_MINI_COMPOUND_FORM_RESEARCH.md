# Forge Mini next curriculum: original connected multi-operation shapes

Code: app/src/main/java/com/assetwright/app/mini/NativeComposedFormLab.kt

The geometry-aware v5 model studies exactly six single native operations.
A complete game-asset geometry student must eventually learn SEQUENCES of
operations, and dependency rules between their corresponding real meshes.

As a foundation, NativeComposedFormLab now supports a typed, bounded
research-only modeling program of **two to four distinct operations**,
with one canonical order from superellipse profile and section loft
through fairing, recess, twist and sweep.

This engine uses ONLY AssetWright's original Kotlin AdvancedFormLab.
Each source operation produces an indexed mesh with the same exact
602 corresponding vertices and the same connected triangle topology.
The program composes their measured vertex displacement fields relative
to a common undeformed Kotlin baseline; no pretrained outside AI or
third-party 3D generator is involved.

Its constraints reject repeated operations, out-of-order commands,
excessive strengths, collapsed triangles, non-positive closed-shell
volume, inconsistent source topology and nonfinite coordinates.
NativeComposedFormLabTest checks actual original GLB encoding,
connected indexed topology, 2/3/4 operator programs and fail-closed
invalid programs.

**This is an additive compound-displacement field, not exact sequential
noncommutative constructive solid geometry or boolean CAD.** It is
a starter *program grammar and original geometry source generator*,
not a trained multi-operation program-prediction neural model.
It is isolated from Android's existing vehicle renderer.

Next actual learning step (requires a separate, fresh training cohort):
create paired source scenes and explicitly labeled original operation
programs; train a small program decoder to predict operation order,
count and strengths; test family-disjoint GLB geometry and topology
against a replay-only baseline; preserve learned weights with
source hashes without replacing existing verified models.

Never reuse already inspected v1-v5 blind families as new validation,
and never claim arbitrary text-to-3D or neural CAD planning until an
independent native GLB task demonstrates those capabilities.
